# Training and retaining a candidate

This directory contains two different experiments. Both use synthetic examples. Do not reuse the application holdout as a training set.

**Trained on this laptop:** `train_guard.py` fits a small logistic classifier on changed evidence/claim pairs, using a 270-pair training split and a separate 90-pair calibration split. On a 40-pair handwritten challenge it flagged 12/20 unsafe changes, missed 8/20 and wrongly held 1/20 accurate paraphrases. See `guard-report.json` for the examples, scores and threshold. ResumeForge uses the saved parameters in `resumeforge/data/risk-guard.json` only as an additional veto in the sequential workflow. Passing this classifier does not establish truth. The LLM still reviews changed text. This classifier is not a Qwen adapter; see the actual on-device [reviewer training](../laptop_adapter/README.md) and [writing preference training](../writer_adapter/README.md) experiments.

**Prepared for a CUDA PC, not run on this Mac:** `train_pc.py` performs supervised QLoRA on the official Qwen3.5-4B checkpoint at a pinned revision. The training manifest records 300 conversations from 90 synthetic scenarios and 100 validation conversations from 30 other scenarios. These cover which source to emphasize, concise/detailed writing and evidence review. Only assistant completion tokens contribute to loss. The base and vision tower remain frozen. The script refuses to start a CPU fallback and will not replace a production model.

1. Record the PC's exact GPU, VRAM, RAM and drivers. Choose a CUDA-compatible Python/PyTorch environment using [PyTorch's installer](https://pytorch.org/get-started/locally/). Install compatible versions of Transformers (including Qwen3_5ForConditionalGeneration), PEFT, accelerate and bitsandbytes in that environment. [PEFT LoRA reference](https://huggingface.co/docs/peft/main/package_reference/lora).
2. Evaluate the unmodified checkpoint on a frozen set using the local endpoint first. Inspect datasets and their digests. These synthetic labels are starter supervision, not an exhaustive representation of real resumes.
3. Run `python training/train_pc.py --smoke --out pc-smoke` to check compatibility, token masking, loss and peak memory. Then run `python training/train_pc.py --epochs 1 --out pc-candidate` in a fresh directory. This recipe has not yet been validated on your PC; the model and dependencies download on that machine.
4. Serve the candidate locally with the same decoding settings and template as the base, then score the same unseen tasks. Do not deploy based on training loss, validation loss or quick smoke results alone. Compare false approvals, valid requests refused, successful requested edits, and final page fit. Keep the base if there is no repeatable improvement.
5. After examining a held-out failure, keep it as regression coverage. Add new blinded, representative cases before claiming generalization. Human-reviewed real examples can be added with your explicit consent and role/evidence provenance; none were used in the supplied datasets.

The actual model credit/license and frozen revisions are documented in the main README and laptop experiment. The adapter or checkpoint remains a candidate until evaluated; this project has no automated application submission.
